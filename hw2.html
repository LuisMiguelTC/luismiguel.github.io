1. Elliptic Curve Cryptography (secp256k1 Toy Scheme)

In this section, we review the toy cryptographic scheme based on the secp256k1 elliptic curve equation over a finite field F_p:

y^2 = x^3 + 7 (mod p)

  • Key Generation: The private key d is a secret integer chosen from a small, bounded range. The public key Q is computed via scalar multiplication of the generator point G: Q = d * G.
  • Encryption (ElGamal-style): To encrypt a message point M, we generate an ephemeral random integer k, compute C1 = k * G and C2 = M + (k * Q). The ciphertext is the pair (C1, C2).
  • Decryption: We compute the shared secret S = d * C1 and subtract it from C2 to recover the message point: M = C2 - S.

2. The Caesar Cipher & Comparative Analysis

To compare modern asymmetric primitives with classical cryptography, we implement the Caesar cipher to encrypt and decrypt the same message.

# Caesar Cipher Implementation in Python
def caesar_encrypt(plaintext: str, shift: int) -> str:
    ciphertext = []
    for char in plaintext:
        if char.isalpha():
            base = ord('A') if char.isupper() else ord('a')
            ciphertext.append(chr((ord(char) - base + shift) % 26 + base))
        else:
            ciphertext.append(char)
    return "".join(ciphertext)

def caesar_decrypt(ciphertext: str, shift: int) -> str:
    return caesar_encrypt(ciphertext, -shift)

# Example Usage
msg = "CYBERSECURITY"
shift_key = 3
encrypted_msg = caesar_encrypt(msg, shift_key)
decrypted_msg = caesar_decrypt(encrypted_msg, shift_key)
print(f"Encrypted: {encrypted_msg}")
print(f"Decrypted: {decrypted_msg}")

Comparison: ECC vs. Caesar Cipher

Feature Caesar Cipher ECC (secp256k1 Toy Scheme)
Type Symmetric Substitution Cipher Asymmetric Public-Key Cryptosystem
Key Space Extremely small (K = 26) Large theoretically (2^256), restricted in toy scheme
Procedures Modular shift arithmetic (mod 26) Point addition and scalar multiplication over finite fields
Statistical Properties Preserves frequency distribution (letters map deterministically). Hides frequency properties via ephemeral key randomization.

3. Statistical Cryptanalysis of the Caesar Cipher

Because the Caesar cipher preserves single-letter frequencies, we can automatically recover the key using Chi-Square (chi^2) statistical analysis against standard English letter frequencies.

import string

ENGLISH_FREQS = {
    'A': 0.08167, 'B': 0.01492, 'C': 0.02782, 'D': 0.04253, 'E': 0.12702,
    'F': 0.02228, 'G': 0.02015, 'H': 0.06094, 'I': 0.06966, 'J': 0.00153,
    'K': 0.00772, 'L': 0.04025, 'M': 0.02406, 'N': 0.06749, 'O': 0.07507,
    'P': 0.01929, 'Q': 0.00095, 'R': 0.05987, 'S': 0.06327, 'T': 0.09056,
    'U': 0.02758, 'V': 0.00978, 'W': 0.02360, 'X': 0.00150, 'Y': 0.01974, 'Z': 0.00074
}

def break_caesar(ciphertext: str):
    best_shift = 0
    lowest_chi2 = float('inf')
    clean_text = [c.upper() for c in ciphertext if c.isalpha()]
    n = len(clean_text)
    if n == 0: return 0, ciphertext

    for shift in range(26):
        decrypted = caesar_decrypt("".join(clean_text), shift)
        chi2 = sum(((decrypted.count(char) - (ENGLISH_FREQS[char] * n)) ** 2) / (ENGLISH_FREQS[char] * n) for char in string.ascii_uppercase)
        if chi2 < lowest_chi2:
            lowest_chi2 = chi2
            best_shift = shift

    return best_shift, caesar_decrypt(ciphertext, best_shift)

Discussion & Security Implications

  • Caesar Attack vs. ECC Toy Attack: The Caesar attack relies on linguistic redundancy and statistical distributions over a large corpus, whereas the restricted ECC attack exploits computational feasibility due to an artificially small key space.
  • Why Full-Scale ECC is Secure: In a standard secp256k1 implementation, the private key space is 256 bits (approx. 10^77 possibilities), making exhaustive search computationally impossible due to the hardness of the Elliptic Curve Discrete Logarithm Problem (ECDLP).
  • Toy Scheme Vulnerabilities: Weaknesses in toy schemes arise primarily from parameter constraints (restricted key space) and occasionally implementation flaws such as nonce reuse or lack of point validation.
